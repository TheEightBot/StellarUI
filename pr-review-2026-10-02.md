## ReactiveUI 25 — deferred

25.0.0 (2026-09-27) moves binding to the source-generated ReactiveUI.Binding ([release notes](https://github.com/reactiveui/ReactiveUI/releases/tag/25.0.0), [migration guide](https://reactiveui.net/documentation/upgrading/reactiveui-binding-migration)).

Trial build against 25.1.1 (local branch `spike/reactiveui-25`, not pushed): compiles after namespace changes in Stellar.Avalonia and Stellar.WinUI and dropping the explicit `ReactiveUI.SourceGenerators` references; 259/259 unit tests pass. But:

- `Bind`/`BindTo` through private view fields get no generated binding and throw at run time (RXUIBIND003/021 in Stellar.AvaloniaSample). That is the usual Stellar view pattern, so consumers must change code.
- Bindings now marshal writes to the UI thread and coalesce bursts.
- `ICreatesCustomizedCommandRebinding` is gone, so #48's fix does not carry over.
- MAUI projects not built against 25.

## #48 — BindCommand rebinding (merged, b8868d5)

- Bug is real: in ReactiveUI 24.0.0 and 24.3.0, `CommandBinderImplementation.BindCommandInternal` creates the new binding before disposing the old one, and the old one's dispose restores the command it captured. Reverting the fix makes 8 of the 21 new tests fail.
- Added on the branch: a CI step running `Stellar.Maui.UnitTests` in the MAUI packages job (the tests were never run by CI), and a merge of `develop`.
- `MauiCommandRebinding` was `public` but must be deleted on the move to ReactiveUI 25; made `internal` before merge.
- Inferred, untested: Avalonia, Uno and WinUI have the same bug (only WPF has an upstream customizer).

## #47 — ItemsView recycling (merged, 7f5280b)

- Claims hold against dotnet/maui 10.0.90 and AndroidX RecyclerView (`DEFAULT_MAX_SCRAP = 5` per view type).
- Not Android-only: the logic is in shared `MauiViewManager`, and iOS is affected too.
- As submitted it was default-on: for up to 5 recycled rows per list, `Bind`/`Initialized`/`Activated`/`Deactivated` no longer run per row, so a cell that reads its item imperatively in `Bind()` shows stale data. Changed to opt-in before merge: the default is 0 and a list opts in with `RecycledItemViewLimit(n)`.
- Minor, still open: little benefit under a `DataTemplateSelector`; `RecycledItemViewLimit` has XML docs but no README mention. Lowering the limit now releases already-kept views.
- Added on the branch: iOS recycle-order tests, the same CI test step, and a merge of `develop`.
- Pre-existing, separate: with the iOS recycle order and a view model per row, the row's view model is never unregistered.

Both PRs added `Stellar.Maui.UnitTests`. #48's branch was merged into #47's and the duplicate "Test Stellar.Maui" CI step removed before #47 merged; 195 MAUI tests on the combined branch.
